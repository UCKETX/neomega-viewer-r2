# neOmega-R2

在浏览器里用射线渲染 Minecraft Java 和基岩版存档。服务端读取世界，浏览器通过 WebGPU 或 WebGL 2 绘制。视野内的栏杆、楼梯、花和跨格模型都有完整的静态外观；靠近时还可以看到附魔台上活动的书。

项目沿用 neOmega Viewer 的存档浏览方式，渲染核心换成了 neOmega R2。默认场景 **Möbius** 是一圈海晶灯构成的莫比乌斯环，悬在傍晚的海面上。[前身 neOmega Viewer](https://github.com/CMA2401PT/neomega-viewer) · [neOmega R2 渲染核心](https://github.com/CMA2401PT/neomega-r2)

## 下载与启动

从 [GitHub Releases](https://github.com/CMA2401PT/neomega-viewer-r2/releases) 选择对应系统的压缩包。程序已内嵌网页、渲染器和默认材质。

| 系统                | 压缩包名称中的平台 | 解压后运行            |
| ------------------- | ------------------ | --------------------- |
| Windows x64         | `windows-amd64`    | 双击 `neOmega-R2.exe` |
| macOS（Apple 芯片） | `macos-arm64`      | `./neOmega-R2`        |
| Linux x86-64        | `linux-amd64`      | `./neOmega-R2`        |
| Linux ARM64         | `linux-arm64`      | `./neOmega-R2`        |

启动后，打开终端中粗体白色的本机地址，默认是 <http://127.0.0.1:2412>。同一局域网里的设备可打开灰色的 IPv4 地址。**文件选择器浏览的是运行服务那台机器上的文件**，同一服务的页面共享当前存档。默认监听 `0.0.0.0:2412`，仅在本机使用可运行以下命令：

```sh
./neOmega-R2 -listen 127.0.0.1:2412
```

右上角的 `[webGPU]` 或 `[webGL]` 显示实际使用的后端。支持 WebGPU 的浏览器在本机回环地址和 HTTPS 下默认使用它，普通局域网 HTTP 使用 WebGL 2。两种后端都可用时，点击标签即可切换并重新加载页面。手机横屏和竖屏都可使用，竖屏时底栏折成两行。

## 打开存档与结构

点击底部文件夹，选中来源后点击“打开”。选择器默认从 Viewer 进程的工作目录开始，可打开的项目排在前面，输入名称可筛选当前目录。页面会分别记住成功选择的存档和材质包，点击「工作目录」可随时返回起点。

在打开选项里可以选择维度、调整结构转换预算或关闭 Bedrock 邻接修复。双击目录进入下一级，转换进度显示在面板内。点击底部的世界名可查看路径、维度和加载信息，关闭存档会回到 Möbius。

| 来源                      | 支持的输入                                                 |
| ------------------------- | ---------------------------------------------------------- |
| Java 存档                 | 世界目录、`level.dat`、PackFS 单文件（`.pack`、`.packfs`） |
| Bedrock 存档              | 含 `db` 的世界目录或其 `level.dat`                         |
| 转换为 Java 存档          | `.schem`、`.schematic`、`.litematic`、`.nbt`               |
| 转换或解包为 Bedrock 存档 | `.mcstructure`、`.mcworld`                                 |

原生存档和 PackFS 以只读方式打开。结构文件默认转换到源文件旁边，例如 `城堡.schem` 对应 `城堡/`。在文件选择器中指向一个目录，点击行右侧的「设置为转换输出目录」，之后所有转换都放在该目录下；在「打开选项」里可查看当前目录，或点击「重置为源文件旁」。不同路径或格式只要去掉扩展名后同名，就直接打开已有结果。若想重新转换，先移走旧结果。

Java 维度使用存档内的相对目录，包括主世界 `.`、下界 `DIM-1`、末地 `DIM1` 和自定义的 `dimensions/<命名空间>/<路径>`。Bedrock 使用 `0`、`1`、`2`。打开存档后也可以在场景信息中切换维度。可显示的方块高度为 **Y = −64～447**，场景信息会统计已接收区域里超出范围的子区块。

```sh
./neOmega-R2 -world /path/to/world.pack -dimension DIM-1
./neOmega-R2 -world /path/to/bedrock-world -dimension 1 -bedrock-fix=false
./neOmega-R2 -world 城堡.schem -structure-memory-mib 1024 -structure-workers 4
```

结构转换默认使用 512 MiB 工作预算，最低 64 MiB。写出并发默认设为 `0`，由转换器按 CPU 和预算决定。Bedrock 邻接修复根据周围方块调整栅栏连接、楼梯拐角等属性，只影响内存中的显示结果。`-h` 可查看启动选项，`-version` 打印版本。

## 飞行、地图与渲染

| 操作                 | 鼠标与键盘                   | 触屏                     |
| -------------------- | ---------------------------- | ------------------------ |
| 转向                 | 拖动场景                     | 单指拖动场景             |
| 水平移动             | WASD，方向跟随相机的水平朝向 | 左侧十字键               |
| 升降                 | 空格上升，Shift 下降         | 右侧上下键               |
| 地图平移、旋转、缩放 | 左键拖动、右键拖动、滚轮     | 单指平移，双指旋转和缩放 |

滚轮可沿视线前后移动，按住 Shift 滚动会加大步长。点击底部 X、Y、Z 读数可编辑坐标，回车跳转。地图上的方块也可以点选，“跳转”会把相机移到选中方块上方两格。左上角显示实际渲染分辨率和帧率，齿轮打开设置，设置保存在当前浏览器。

### 画质、视距与时间

- **预览**默认使用光影档。体素档用纯色表现方块，基础档显示模型和贴图，光影档加入阴影、雾和水面效果。切换时按需编译，面板会提示进度。[四档渲染器](https://github.com/CMA2401PT/neomega-r2/blob/main/r2/README.md#四档渲染器)
- **近景半径**控制特效和方块实体外观，默认 2 区块，可调为 1～16。**远景半径**控制静态方块，默认 32 区块，可调为 16～96。默认窗口覆盖 1024×1024×512 方块。密集存档出现区域池容量不足时，可降低远景半径。
- **渲染分辨率**默认是窗口 CSS 尺寸的 1.5 倍。可选窗口的 0.5～2 倍，或屏幕原生像素的 1～4 倍。所有倍数都指宽和高：4× 的总像素数是 1× 的 16 倍，显存不足时请降低倍数。
- **时间流逝**默认开启，一昼夜约 4 分钟。相机停下后昼夜继续推进，左上角继续显示 FPS。Möbius 从 19:00 开始，从开场场景进入存档时切到 10:00。
- **静止时累积**会暂停昼夜。移动相机时保持当前时刻，停下后从第一个样本开始累积。两个开关都可以关闭，这时保持当前时刻，停下后也不累积。
- 在「设置 → 光照」中开启**手动放置太阳**会暂停时间流逝，可以在同一光照下静止累积。再次开启时间流逝会关闭手动放置太阳和静止累积，太阳恢复沿昼夜轨道运行。

「设置 → 调试」可在实时画面上查看遍历与求交热力图、求交路径，也可分别切换空域与均匀立方体跳跃、跨格片段。页内说明解释颜色含义。

### 保存画面和建筑

| 入口                   | 保存内容                                                      | 何时完成                                                   |
| ---------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| 右上角「导出当前画面」 | 当前预览档的 PNG，默认按屏幕像素的两倍边长、4×4 超采样渲染        | 采满后自动保存；1×、2× 保留 2400 万像素保护，显式选择 3×、4× 时仅按纹理尺寸上限等比缩小 |
| 右上角「拍照」         | 累积渲染的 PNG，最多 4 次反弹，照片默认使用屏幕像素的两倍边长 | 画面持续收敛，满意时再次点击保存，Esc 放弃                 |
| 底部「导出离线 HTML」  | 当前维度的静态世界、视角、材质与显示设置，可在另一台设备上继续浏览      | 区域写入完成后下载单个 HTML                                |

底部问号打开操作帮助，按界面顺序说明图标的用途。

右上角的设置可分别调整导出画面和拍照的输出尺寸（1×～4×）及超采样网格（1×1、2×2 或 4×4）。比较抗锯齿时保持 PNG 尺寸和视角不变：4×4 在每个输出像素内取 16 个样本并平均亮度，不改变 PNG 尺寸，也不影响实时预览。拍照默认使用 1×1，在像素内随机取样；选 4×4 时每四轮分访四个象限，16 轮走完整个网格，之后继续累积直至手动保存。

「设置 → 画面 → 静止累积与拍照降噪」提供「关闭、轻度、中度、高度」，默认选中「轻度」。三个降噪档都只取周围一圈像素（3×3）。档位越高，参与平滑的色差范围越宽，平滑后的颜色占比越大。切换档位会保留已经累积的样本。

## 全屏地图

右上角的地图图标把同一画布切换成正交俯视图。正交投影让所有主射线平行，地图上的同一距离不会因远近而缩放。地图沿用已加载的静态模型与核心射线求交，特殊对象隐藏，远景雾关闭。主相机的位置和朝向保持不变，静止时也能逐帧累积。

地图以主相机位置为中心，初始北方朝上、俯角 70°。左键拖动平移，右键拖动旋转和调整俯角，滚轮围绕光标缩放。触屏上单指拖动平移，双指同时旋转和缩放，缩放时两指中点下的地面跟随手指。手指数变化后从当前视图继续操作。底部滑块也可以缩放。鼠标单击或触屏轻点方块显示整数坐标与命中面，“跳转”把主相机移到方块上方两格并收起地图。再按一次地图图标或按 Esc 即可返回原视图。点到尚未加载的区域时，地图把窗口移过去，发布完成后自动沿原来的射线再拾取一次。

左上角显示当前输入设备的地图操作提示。右上角保留渲染工具，可直接拍摄鸟瞰图。

地图平移只改变远景窗口中心，近景对象仍跟随主相机。地图叠加层显示主相机朝向和选中位置，收起地图后远景窗口回到主相机附近。

画面在地面上的长边超过远景直径（远景半径 × 2 区块）的 √2 倍时，地图切换为区块占用图；阈值随远景半径调整。占用图以浅色表示来源中存在的区块，用来浏览整个场景的分布；点击某处会定位并放大回射线尺度。

区块占用表经 R2Link 的 `chunks` 请求取得，编码见 [占用表](https://github.com/CMA2401PT/neomega-r2/blob/main/go-link/README.md#占用表)。每个世界请求一次，外部数据源更新世界描述时重新请求；服务端对每个存档会话只扫描一次区域文件。Java 存档按覆盖 32×32 区块的 `.mca` 文件建立索引，Möbius 按同样的粒度登记环所在的区块；它们都与流式加载的 8×8 区块区域采用不同粒度。网页把每条记录变成 32×32 的离屏位图。可见范围内的区域位图先在同一张离屏画布中按区块坐标拼接，再整体按地图相机缩放旋转。采样使用最近邻，区域交界处不会因分别绘制的边缘抗锯齿而留下浅色接缝。

## 曙光实验（Dawnlight 风格）

在「设置 → 画面」点击「应用曙光光影」，或点击「还原原画面」恢复此前的光照和渲染档。这个实验受 [Dawnlight](https://dawnlight.eltancex.top/) 的体积光、大气与水面效果启发，**不是原光影包加载器**，没有使用其代码或资源。它给 R2 光影档加了以地形阴影求交为基础的分层体积散射，以及可在水面反射中看到的程序云层；水面仍由 R2 本身计算反射和波纹。应用曙光后太阳跟随时间滑条；如果需要固定构图，可以手动放置太阳。静止累积、拍照和离线 HTML 保留这套参数。近地雾有额外的 GPU 开销，可以减小渲染分辨率，或在光照页关闭太阳辉光。火把体积发光、泛光、动态天气与原包的完整效果尚未移植。

## 生存战争地图

文件选择器和 `-world` 支持只读打开 Survivalcraft 2.4 区域格式（RGN1）的 `.scworld`。只显示存档里的区块，不生成新地形。打开时使用地图内置的 PNG `.scbtex`；没有内置贴图时使用 [生存战争 2.4 官方方块图集](https://kaalus.wordpress.com/media/)（首次下载、校验后缓存）。可用 `-survivalcraft-texture /path/to/Blocks.png` 指定本地图集。生存战争不套用 Minecraft 材质；换到不同方块图集时，页面会重载渲染器，切换 WebGPU／WebGL 2 时继续使用同一套生存战争贴图。

网页「设置 → 画面 → 材质包」可以选择、应用生存战争 `.scbtex` 或 PNG 方块图集。换图集保留当前世界、已导入模组和视角；「恢复默认」优先使用存档内置图集，否则使用 2.4 原版。PNG 图集必须是 128、256、512 或 1024 像素的正方形，非 PNG 格式不支持。该功能不读取 Minecraft 材质包，也不会自动给未知模组方块补定义。

RGN1 存档的世界信息支持 `Project.xml` 和使用 `[类型, 值]` 字段的 `Project.json`；两者同时存在时优先用 XML，不会使用 `Project.bak` 或 `Project.temp`。地形格式以 ZIP 内的区域文件为准，不以世界信息中的版本号（例如 `2.3`）决定。

网页和命令行都可导出带生存战争贴图的离线 HTML，例如：

```sh
./dist/neOmega-R2 export -o palace.html '/path/to/palace.scworld'
```

家具、楼梯和栏杆造型仍有近似；旧式单文件地形、ASTC 材质、实体、标牌文字及模组逻辑不支持。生存战争的材质随本机 Viewer 会话或 HTML 提供，通用外部 R2Link 客户端仅有 Minecraft 状态表时无法直接显示这些方块。

原版可放置方块均有静态预览映射。电路接线、门、活塞、部分植物和家具的外形为近似；不执行电路或动画。未适配的模组方块仍显示亮紫色占位，便于分辨存档中的内容和渲染缺口。

## 使用材质包

在“设置”里选择服务端机器上的材质包 zip 或目录，也可以输入完整路径后点击“应用”。Java 包根目录应直接包含 `assets`。基岩包从 `textures/blocks` 读取名字能对应的方块 PNG、高度图和材质参数。切换只改变共享静态模型使用的贴图，保留当前存档与视角；缺失或损坏的单张图片回退原版。“恢复原版”清除覆盖，路径和尺寸设置保存在当前浏览器。

支持颜色图片及同名 labPBR `_n`／`_s` 图片。labPBR 把法线、AO、高度、高光和自发光等属性保存为数据通道，核心会按颜色图相同的层号或图集区域组织它们。没有配套图时使用默认材质数据。动画贴图按 `.mcmeta` 的首帧显示。

“贴图尺寸上限”默认 128，可选 16～512。完整方块共用一组等大的贴图层，层边长取这些方块用到的最大贴图尺寸，并受上限约束。箱子等复杂模型的贴图在独立图集中按各自尺寸存放。只选 128 上限不会把原版自动放大到 128。较高尺寸同时增加颜色、法线和高光的显存，估算公式见 [核心材质包说明](https://github.com/CMA2401PT/neomega-r2/blob/main/r2/README.md#材质包怎样替换贴图)。

应用通过 `POST /api/textures` 把路径和上限交给核心，响应包含整套贴图及匹配的透明度数据。后台线程用已缓存的存档区域重建镂空分类对应的空间目录，完成后同帧替换 GPU 资源。因此替换树叶或给石头增加透明孔时，颜色、遮挡与阴影依据的是同一份图片，切换不需要重新打开存档或重新下载区域。

例如，直接请求服务生成一份资源快照：

```sh
curl -X POST http://127.0.0.1:2412/api/textures \
  -H 'Content-Type: application/json' \
  -d '{"path":"/path/to/pack.zip","maxSize":128}' \
  -o /tmp/r2-textures.bin
```

这个接口只返回资源，不修改服务端存档会话；网页接收后负责把结果应用到自己的渲染器。

## 导出离线建筑网页

点击底部 HUD 的「导出离线 HTML」下载当前维度。网页以点击时的位置、朝向和视场角开场，内嵌已应用的材质和模型表。播放器沿用当时的日月位置和时间、直射光、天空补光、曝光、薄雾与云影，也保留渲染档位、视距及分辨率。开启“静止时累积”时，打开文件后会重新累积样本。开启“时间流逝”时，时间从导出时刻继续推进。双击 HTML 即可离线浏览，右上角支持切换 WebGPU 和 WebGL 2。

导出会读取该维度区块占用表里的全部静态区域，包含视野外的建筑。每个非空区域单独压缩，浏览时按需解压。沿用 R2 的 Y = −64～447 高度范围和已用调色板，并省略全空气子区块及动态对象。内置场景和提供区块占用表的 R2Link 数据源也可导出。

批处理使用同一个可执行文件的 `export` 子命令。命令行导出默认使用原版材质、自动取景和全部非空维度。`-dimension` 可指定单个维度。省略 `-o` 时，HTML 保存在输入旁，使用相同的基础文件名。命令行转换结构时使用临时目录，导出结束后自动清理。

```sh
./neOmega-R2 export -o pavilion.html pavilion.schem
./neOmega-R2 export -dimension DIM-1 -template my-template.html -o nether.html ./my-world
```

### 自定义导出模板

默认模板在 [internal/snapshot/template.html](internal/snapshot/template.html)。`-template` 可指定自己的 HTML，在正文中保留这两个标记即可沿用离线播放器：

```html
<body>
  <!-- R2_WORLD -->
  <!-- R2_VIEWER -->
</body>
```

`R2_WORLD` 必须出现一次，导出器会在这里写入版本为 1 的 JSON 清单（`#r2-world`）、各维度的区块位图（`#r2-chunks-维度编号`），以及非空区域的 `script[data-dimension][data-r2-region]`。区域坐标格式为 `x/z`，区域内容是 R2Link 的 `EncodeRegion` 二进制，位图和区域均经 gzip 压缩再用 Base64 编码。维度编号见清单中的 `dimensions[].key`。实现了自己播放器的模板可以省略 `R2_VIEWER` 并直接使用这些数据；自定义的脚本、字体和图片也要内联才能随文件离线分发。

## 连接外部数据源

游戏机器人、服务器插件或存档服务可以用 [R2Link](https://github.com/CMA2401PT/neomega-r2/blob/main/go-link/README.md) 提供世界。点击底部的链接按钮，填写数据源的 `ws://` 或 `wss://` 地址：浏览器直接连接数据源，握手成功后才关闭当前存档，连不上时当前世界不受影响。存档名旁的圆点表示连接状态：青色为已连接，橙色闪烁为断线重连。断线时保留最后画面，每 3 秒重试，数据源回来后重新发送全部内容。数据源可以移动相机、更新世界名。关闭按钮断开连接并回到 Möbius。

[java-source](examples/java-source/main.go) 是一个最小的数据源示例。在 Viewer 仓库根目录运行它，即可按浏览器的订阅逐区域发送 Java 存档。

```sh
go run ./examples/java-source -world /path/to/world
# 连接面板填写 ws://127.0.0.1:2414/r2link
```

## 服务端与渲染核心

网页从 `GET /api/world` 获取当前会话。`loaded: true` 表示存在可加载的来源，存档与内置场景都满足这一点。内置场景的 `name` 为 `Möbius`、`path` 为空，并额外携带 `scene`：`ocean` 是海面 Y 坐标，`camera` 包含 `position`、`yaw`、`pitch`，角度使用弧度，`time` 以小时表示开场时刻。顶层 `position` 与开场相机位置一致。存档响应省略 `scene`。`POST /api/world/open` 接收 `path`、`dimension`、`bedrockFix`、`structureMemoryMiB`、`structureWorkers`。默认返回 JSON 会话描述；请求头 `Accept: application/x-ndjson` 时逐行返回 `progress` 消息，最后返回 `world` 或 `error`。`POST /api/world/close` 返回 Möbius 会话描述，关闭会恢复内置场景。

世界内容不走 HTTP 接口：服务端在 `GET /r2link?world=<会话 id>` 上把当前世界作为 [R2Link](https://github.com/CMA2401PT/neomega-r2/blob/main/go-link/README.md) 数据源提供给同源页面，网页用核心的 `r2linkSource` 连接它，和连接外部数据源是同一条路径。会话编号不是当前世界时返回 HTTP 409；打开或关闭世界会断开连到旧世界的页面，页面随即读取 `/api/world` 跟随新世界，别的页面打开的存档也因此同步。

服务端读取和解压存档，仅把调色板条目换成方块哈希（渲染器按资源包的状态表解释），保留压缩格子索引，不生成模型、剔面或合并网格。一个区域包含 8×8 区块；服务端为每个世界保留最多约 64 MiB 的区域缓存，所有连接共用 4 个读取名额。Möbius 的区域在首次读取时生成一次，之后各会话复用，没有特殊对象。

加载范围、后台准备与 GPU 发布由核心的世界会话（[WorldSession](https://github.com/CMA2401PT/neomega-r2/blob/main/r2/README.md#世界会话与数据源)）负责。会话的订阅经 R2Link 交给服务端，服务端优先读取靠近相机的区域，不再需要的区域立即取消读取；后台线程登记跨格片段并生成空域掩码；主线程每帧发布一个完成的区域，未完成部分稍后补齐。移动时复用重叠区域，离开范围的区域撤销候选并回收地址。静态窗口周围保留一圈来源区域，保证边界模型完整。近景视距变化只更新特殊对象；对象候选没有变化的静态区域不重新准备，也不重新传输索引。

### 特殊对象的扩展位置

Go 入口 `cmd/viewer/main.go` 选择需要启用的 effector 和 block actor 处理器。`internal/worlddata.World.Objects` 仅扫描近景中被处理器认领的方块，将状态、位置和 NBT 交给它们。浏览器入口 `web/app.ts` 注册对应类型的外观工厂。工厂返回部件、贴图、包围盒和动画，公共实例层负责格子候选与射线绘制。

附魔台的活动书已通过这条链路接入。block actor 的处理器和传输接口已连通，并通过携带 NBT 的测试处理器验证；旗帜图案、告示牌排版等具体实现尚未添加。详细契约和新增实现的方法见 [核心说明](https://github.com/CMA2401PT/neomega-r2/blob/main/r2/README.md#怎样添加-effector-和-block-actor)。含水方块暂只显示本体，不显示附加水层。

区域池预留 256 MiB，缩小视距回收池内地址，切换场景时释放旧池，并为新来源重新建立池。远景半径超过 48 时，密集存档可能超出容量，此时会显示错误，可降低远景视距。文件会话按相机流式读取固定内容，查看磁盘上的外部修改需重新打开。

## 从源码构建

Viewer 使用 GNU Make、Go 1.25.5 和 Node.js 24。Go 模块和网页构建按相对路径寻找同一工作区中的 R2、存档转换器等依赖。

在新的空目录中，用 `make deps` 从 GitHub 检出[发布锁定的依赖版本](release-deps.lock)：

```sh
mkdir -p apps
git clone https://github.com/CMA2401PT/neomega-viewer-r2.git apps/neomega-viewer-r2
make -C apps/neomega-viewer-r2 deps
```

在已有依赖的工作区，直接构建并运行 Viewer。`make build` 会先构建网页和离线播放器，再把它们嵌入可执行文件。

```sh
cd apps/neomega-viewer-r2
make build
./dist/neOmega-R2
```

在 Viewer 仓库根目录运行 `make build-all`，会从本地源码构建 macOS ARM64、Windows x64、Linux x64 和 Linux ARM64 四个压缩包。开发包默认标记为 `dev`，输出到 `dist/local/`。

`make web` 只构建网页和离线播放器，之后可用 `go run ./cmd/viewer` 启动。`make test` 会构建网页并运行 Go 测试。开发页面时，`-web ./web` 可从磁盘读取宿主页面。更新共享 HUD、渲染核心或嵌入的离线播放器后，需要重新构建可执行文件。

`make version` 显示当前提交上的版本 tag，没有 tag 时显示 `dev`。`make tag` 按本地最新正式 tag 递增补丁号，在当前提交上创建新 tag。可以用 `make tag VERSION=v0.2.0` 指定版本。

依赖升级时，`make update-deps` 会读取各远端默认分支的最新提交，重新生成锁文件。在干净工作区用 `make deps` 验证新依赖能构建后，再提交锁文件。

`make release` 将当前 tag 写入可执行文件，并把四个平台的压缩包放在 `dist/release/`。可以用 `make release VERSION=v0.1.1` 指定打包版本。推送 tag 后，[发布工作流](.github/workflows/release.yml)会使用同一个目标打包。

## 生存战争 .scmod 静态预览

在文件选择器中选中 `.scworld`，再点击列表内的 `.scmod`（也可在模组栏里逐行粘贴 Viewer 所在机器的文件路径），最后点击「打开所选来源」。再次打开存档时可清空模组栏。启动和离线导出使用同一个读入机制：

```sh
./dist/neOmega-R2 -world '/path/world.scworld' -survivalcraft-mod '/path/pack.scmod'
./dist/neOmega-R2 export -survivalcraft-mod '/path/pack.scmod' -o preview.html '/path/world.scworld'
```

`.scmod` 按 ZIP 只读打开，需要 `modinfo.json`。带 `Class Name` 列的分号分隔方块 CSV 可以通过存档的方块注册表匹配类名；也可以在 CSV 用 `BlockIndex` 明确绑定 ID。CSV 可用 `DefaultTextureSlot` 指向存档图集的格子，或用 `Texture` 和 `Model` 声明 PNG、OBJ/DAE 的 ZIP 内路径。也会查找 `Assets/Textures/<类名>.png` 和 `Assets/Models/<类名>.obj/.dae`（可省略类名末尾的 Block）。如果存档未提供注册表或资源文件名不一致，可以在模组 ZIP 根目录添加 `r2-blocks.json`，以实际注册表核对的 ID 或类名明确绑定；不要猜测别的存档里分配的数字：

```json
{
  "version": 1,
  "blocks": [
    {
      "id": 901,
      "class": "DemoTriangleBlock",
      "model": "Assets/Models/DemoTriangle.obj",
      "texture": "Assets/Textures/DemoTriangle.png"
    },
    { "id": 902, "atlasSlot": 78 }
  ]
}
```

未指定模型时预览为有贴图的整方块。支持一个纹理的静态 OBJ（带 UV）以及 COLLADA 的 `triangles`、`polylist`（带 UV），使用单格坐标；模型超出单格时默认等比缩放居中落地，也可以用 `scale` 和 `offset: [x,y,z]` 显式指定。暂不读取场景节点变换、骨骼、动画、多个材质及代码生成的模型；DLL 和脚本不会执行。无法确认绑定的方块仍是紫色诊断占位。
